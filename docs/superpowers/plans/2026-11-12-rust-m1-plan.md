# Rust M1 — event model, Python-compatible serde, `EventLog` and indexes — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `dejafix-core` reads `.dejafix/events.jsonl` exactly as Python 0.4.x does (same accepted lines, same normalised values, same ids for id-less lines), writes every event back byte-identically to `json.dumps(event, sort_keys=True)`, keeps unknown fields, and builds an `EventLog` with open/closed issue, retired event and file → events indexes whose paths match Python's precheck spelling.

**Architecture:** Pure logic lives in `core/` as five modules: `text` (Python string semantics), `json` (Python-compatible JSON formatting), `time` (Python's `normalize_timestamp`), `event` (domain types, line decoding and encoding), `path` (`location_to_file` and precheck's path spelling) and `log` (`EventLog`, built in one pass over a borrowed byte buffer, with indexes). Everything the core needs from the outside world is an argument: the clock and local time zone (`Clock`), the project root and working directory (`PathContext`) and symlink resolution (`PathResolver` trait). `adapters/fs/` reads the file, resolves paths on disk and builds a `PathContext`. Python stays the oracle: the golden tests run the Python functions from `src/` on the same input and compare.

**Tech Stack:** Rust 1.99.1 (edition 2024); serde 1.0.229, serde_json 1.0.154 (features `raw_value`, `float_roundtrip`), jiff 0.2.43, regex 1.13.1, thiserror 2.0.21, sha1 0.11.0; dev: proptest 1.12.0, criterion 0.8.2, tempfile 3.27.0; Python 3.15.2 with dejafix 0.4.0 from `src/` as the oracle.

## What Python does, precisely

The behaviour M1 reproduces, read from `src/dejafix/models.py`, `storage.py`, `staleness.py` and `commands/precheck.py`:

- `read_events`: decodes the file as `utf-8-sig` (one leading BOM dropped), splits with `str.splitlines()` (`\n`, `\r`, `\r\n`, `\v`, `\f`, `\x1c`, `\x1d`, `\x1e`, `\x85`, `\u2028`, `\u2029`), skips lines where `line.strip()` is empty, numbers lines from 1, and runs `Event.from_dict(json.loads(line))`. Python stops on the first bad line; Rust skips it and counts it (spec, "Errors").
- `Event.from_dict`:
  - `id = data.get("id") or stable_event_id(data)`; `stable_event_id` is `"evt_" + sha1(json.dumps(data, sort_keys=True, default=str))[:20]` over the raw parsed object.
  - `timestamp = normalize_timestamp(ts)` when `ts` is truthy, else the current UTC time.
  - `type` must be one of `issue`, `hypothesis`, `attempt`, `fix`, `decision`, `note`.
  - `summary` must be a string; it is stored `strip()`ped and must not be empty.
  - `outcome` ∈ {`worked`, `failed`, `partial`} or null; `capture_source` ∈ {`git_post_commit`, `git_post_revert`, `git_post_merge`, `churn_detector`, `ci_parser`} or null; `capture_confidence` ∈ {`high`, `medium`, `low`} or null.
  - `files = list(data.get("files") or [])`; `auto_captured = bool(...)`.
  - `issue_id`, `command`, `notes`, `git_commit`, `location`, `git_message`, `supersedes` pass through unchanged.
  - Unknown keys are dropped from the object (Python never rewrites the log, so they stay on disk).
- `Event.to_dict`: every dataclass field whose value is not `None`, `[]` or `False` — and because `0 == False` in Python, `0` and `0.0` are dropped too. `json.dumps(..., sort_keys=True)` with the default separators `", "` and `": "` and `ensure_ascii=True`.
- `normalize_timestamp` (Python 3.11+ semantics; the oracle runs 3.15.2): `datetime.fromisoformat(ts.replace("Z", "+00:00"))`, else `datetime.strptime(ts, "%Y-%m-%d %H:%M:%S %z")`, else the input unchanged. A naive result is interpreted in the local time zone. The result is converted to UTC, microseconds truncated, formatted `%Y-%m-%dT%H:%M:%SZ`. A conversion that leaves year 1–9999 raises `OverflowError`, which Python does not catch.
- `normalize_issue_id`: `strip()`, `lstrip("#")`, empty → `None`, all-decimal (`str.isdecimal`, Unicode `Nd`) → `zfill(4)`, else unchanged.
- `location_to_file`: strip whitespace, then `"` and `'`; protect a leading `X:\` or `X:/` drive; remove a trailing `:\d+(:\d+)?` (`$` also matches before one trailing `\n`); a result with `/` or `\` is a file; otherwise only a name whose last `.suffix` (lower-cased) is in `_SOURCE_SUFFIXES` is a file.
- `project_relative`: `\` → `/`; `posixpath.normpath`; a relative result is returned; an absolute one (POSIX or `X:/`) is made relative to the resolved root, lexically first, then after `Path.resolve()`; outside the root it is returned normalised.
- `is_memory_path` and `location_file` (staleness) build on these.
- Indexes: `open_issue_ids` (issue events with a truthy `issue_id` not closed by any fix, newest first, deduplicated), the closed set (`issue_id` of every fix), `superseded_ids` (every event's `supersedes`, any type), and precheck's `_live_event_paths`: for each event not retired, `own_paths = {rel(f) for f in files} ∪ {rel(location_to_file(location))}`; if empty, the paths of the **last** issue event with the same `issue_id` (any event type inherits, not only attempts).
- `resolve_event_ref`: exact id, else a unique prefix of the hex part; messages "Empty event reference", "No event matches '<ref>'. Use `djf search <text>` to find the event id (shown as evt_...).", "Event reference '<ref>' is ambiguous (<n> matches) — use more characters of the id.".

## Decisions a reviewer may question

1. **`Event` is flat, `EventKind` has no payload.** The spec sketches `Attempt { outcome }` and `Decision { supersedes }`. Python accepts any field on any type and reads them that way: `superseded_ids` takes `supersedes` from every event, an `outcome` on a note is valid and written back. Kind-specific payloads would either drop such fields (breaking byte-identical output) or change what retires what. Invariants that do hold are carried by newtypes instead (`Summary` is stripped and non-empty, `Outcome` and the capture enums are closed sets).
2. **The Python JSON formatter moves to `core/json/`, not `adapters/fs/`** as the M0 hand-over suggested. Decoding a line without an id needs the same formatting to compute `stable_event_id`, decoding is pure, and `core` may not import `adapters`.
3. **The clock and the local time zone are arguments** (`Clock { now, zone }`). Python fills a missing timestamp with "now" and reads a naive timestamp in local time; injecting both keeps the core pure and lets the golden test pin `TZ`.
4. **`EventLog<'a>` borrows the byte buffer** (`&'a [u8]`), so unescaped strings are never copied. The MCP cache in M4 needs an owner for buffer and log together; M4 decides between a re-parse and a self-referential cell (`self_cell`). No such crate is added now.
5. **Known fields with a type Python passes through but Rust cannot type** (a number in `issue_id`, an object in `location`) are kept verbatim in `extra`, so the line still round-trips; the indexes ignore them. Falsy values Python drops (`null`, `false`, `0`, `[]`) are dropped.
6. **Documented divergences, all on hand-edited lines Python itself would mostly reject or mangle.** Rust skips (and counts) a line that Python would accept only in these shapes; each has a unit test:
   - `files` as a string or object (Python turns `"ab"` into `["a", "b"]`) or a `files` array with a non-string element;
   - a truthy `id` that is not a string;
   - JSON Python's `json` module accepts but RFC 8259 does not: `NaN`, `Infinity`, lone surrogates, numbers overflowing `f64`.
   In unknown fields, integers beyond 64 bits are written back as floats and `-0` as `-0.0`; this only matters if Rust ever rewrote such a line, which it never does.
   Timestamps follow Python 3.11+ `fromisoformat`; Python 3.10 users of 0.4.x get a stricter parser, which Rust does not reproduce.
7. **The file index holds live events only**, as precheck's `_live_event_paths` does. Retired events stay in `events()` and in the retired set.
8. **New dependencies:** `sha1` (RustCrypto; stable ids need SHA-1 and the standard library has none — chosen over `sha1_smol` because Context7 documents it), serde_json's `raw_value` feature (unknown fields borrowed without parsing) and `float_roundtrip` feature (without it serde_json parses some floats one ulp away from Python, which proptest found), `proptest` and `criterion` (planned dev-dependencies in the spec).
9. **Python for the golden tests:** the worktree gets its own git-ignored `.venv` whose `site-packages` points at the main checkout's environment through a `.pth` file, so no network access is needed. `PYTHONPATH` already makes `src/` of this worktree win over the editable install.

## Found during implementation

- **Python 3.15 runs the C `fromisoformat`, not `_pydatetime.py`.** `Modules/_datetimemodule.c` (tag v3.15.2) is more lenient: it ignores junk between the time and the offset (`2026-05-12 21:07 +0000` parses), reads `2107` after a numeric separator as hour `10`, finds the first of `Z`/`+`/`-` rather than `-` first, and treats a bare trailing separator as an error. `core/time/iso.rs` ports the C functions (`_find_isoformat_datetime_separator`, `parse_isoformat_date`, `parse_hh_mm_ss_ff`, `parse_isoformat_time`, `datetime_fromisoformat`); the golden scalar corpus (1,800 timestamps) agrees with Python.
- **A naive timestamp is only valid when one day before and after it stays inside years 1–9999** — CPython probes the local offset there. The UTC result is computed on civil date-times, because `jiff::Timestamp` ends at `9999-12-30T22:00Z` while Python reaches `9999-12-31T23:59:59Z`.
- **Unicode versions differ by ten digits.** Python 3.15 knows the Unicode 17 digits U+11DE0–U+11DE9; regex 1.13.1 does not. An issue id or line suffix written in those digits is the only effect; the golden test pins exactly this difference.
- **Python's precheck crashes on a non-string `location`** (`AttributeError` in `location_to_file`); Rust keeps such a line and ignores the field. The index comparison leaves that one corpus line out.
- **On Windows, `FsResolver` does not resolve UNC paths** (`//host/share/…`, `\\host\share\…`). Python's `Path.resolve` would open an SMB connection to whatever host a log line names, which leaks the user's NTLM hash to a hostile repository; such a path stays as written instead.
- **serde_json stops at nesting depth 128**; Python's `json` allows about 1,000. A deeper line is skipped and counted.
- **Line splitting was a quarter of the load time;** a byte pre-filter cut it by a third. Loading the 3,000-event fixture (0.65 MB) takes 2.4 ms and the 30,000-event one 25 ms, about 270 MB/s; serde_json parsing to `Value` alone is about 360 MB/s on the same input. A 2.2 MB real log extrapolates to about 8 ms, which leaves little of the edit hook's 10 ms in M3: M3 should profile the index pass (per-event path vectors) before adding work.

```rust
pub fn write_python_json<W: Write, T: Serialize + ?Sized>(
    writer: &mut W,
    value: &T,
) -> Result<(), serde_json::Error> {
    value.serialize(&mut Serializer::with_formatter(writer, PythonJsonFormatter))
}

pub fn write_canonical<W: Write>(writer: &mut W, value: &Value) -> Result<(), serde_json::Error> {
    write_python_json(writer, &Sorted(value))
}

struct Sorted<'v>(&'v Value);

impl Serialize for Sorted<'_> {
    fn serialize<S: Serializer>(&self, serializer: S) -> Result<S::Ok, S::Error> {
        match self.0 {
            Value::Array(items) => serializer.collect_seq(items.iter().map(Sorted)),
            Value::Object(map) => {
                let mut entries: Vec<_> = map.iter().collect();
                entries.sort_unstable_by(|left, right| left.0.cmp(right.0));
                serializer.collect_map(entries.into_iter().map(|(key, value)| (key, Sorted(value))))
            }
            scalar => scalar.serialize(serializer),
        }
    }
}

pub fn is_python_falsy(raw: &RawValue) -> bool {
    match raw.get().as_bytes().first() {
        Some(b'n' | b'f') => true,
        Some(b'[') => raw.get().trim_start_matches('[').trim_start().starts_with(']'),
        Some(b'-' | b'0'..=b'9') => serde_json::from_str::<f64>(raw.get()).is_ok_and(|number| number == 0.0),
        _ => false,
    }
}
```

impl<'a> Timestamp<'a> {

    pub fn instant(&self) -> Option<jiff::Timestamp>;

After the pass: open issues by walking issue events newest first (deduplicated, not closed); the file index from own paths, else the inherited paths of the last issue event with the same id, skipping retired events. `query.rs` holds the accessors and `resolve_event_ref` (Python strip on the reference, exact match, then prefix of the part after `evt_`).

```rust
#[derive(Debug, thiserror::Error)]
pub enum StoreError {
    #[error("cannot read {path}")] Read { path: PathBuf, #[source] source: io::Error },
}
pub struct FsResolver;
impl PathResolver for FsResolver { fn resolve(&self, path: &str) -> Option<String>; }
pub fn read_events_file(mem_dir: &Path) -> Result<Vec<u8>, StoreError>;
pub fn path_context(root: &Path) -> Result<PathContext, StoreError>;
```

`FsResolver::resolve` ports non-strict `Path.resolve()`: make the path absolute against the current directory, `fs::canonicalize` the longest existing ancestor, append the rest; `None` on error. `path_context` canonicalises `root` (error → `StoreError::Read`), reads `std::env::current_dir` canonicalised (fallback `/`, as Python's `_cwd_posix`), converts both to `/` separators, and sets `fold_case = cfg!(windows)`. `read_events_file` is `fs::read(mem_dir.join("events.jsonl"))`.

**Context7 checks:** `std::fs::{read, canonicalize}`, `std::env::current_dir`, `Path::{ancestors, strip_prefix, components}`, `cfg!`.

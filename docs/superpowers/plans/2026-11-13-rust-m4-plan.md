# Rust M4 — MCP server, `brief` and `global` — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `djf-mcp` serves dejafix's 19 MCP tools over stdio with Python's names, parameters, descriptions, reply texts and server `instructions`, routes every call to a project (pinned root, `project` argument, active project, working folder, the only registered project), and keeps a per-project event-log cache validated by one `stat`. `djf brief` and `djf global` work as in Python 0.4.x. The score and context logic behind `get_score` and `get_context` lives in the core.

**Architecture:** Every reply text is a pure function in `core/`: the score (`core/score`), the context block (`core/context`), the session start (`core/session`), the project resolution decision (`core/resolve`), the MCP reply formats (`core/reply`) and the brief and global-memory renderings (`core/brief`, `core/global`). `wiring/mcp/` composes them with the filesystem and git into one synchronous function per tool, behind a `McpState` that owns the cache. The binary crate's `mcp/` is the only place with `tokio` and `rmcp`: it declares the tools (static JSON schemas equal to Python's), parses arguments, runs each tool body on the blocking pool and turns the outcome into a `CallToolResult`. `cli/memory/` adds `djf brief` and `djf global`. Python stays the oracle: the golden harness drives both servers over stdio with the same JSON-RPC requests.

**Tech Stack:** Rust 1.99.1 (edition 2024). New dependencies, pinned exactly to the latest stable release: `rmcp` 3.10.0 (features `server`, `transport-io`; dev: `client`), `tokio` 1.54.1 (features `rt`, `macros`, `io-std`; binary crate only). Python 3.15.2 with dejafix 0.4.0 from `src/` and `mcp` 2.3.0 as the oracle; git 2.56.

## Changes to the milestone table or the compatibility contract that need the user's approval

None in this plan. Two items may come up during implementation and are then reported instead of decided:

1. **The `precheck_file` budget and git.** Python's `precheck_file` asks git for churn (`git log --since=30.days.ago --oneline -- FILE`) and staleness (`git log --format=%cI -- FILE`) for every checked file that has events. One `git log` process costs about 11 ms on this machine (measured 2026-11-13, load average 5–11; `/usr/bin/true` 2.3 ms). The cache removes the parse, so a file without events, or a project outside git, can meet 5 ms; a file with events cannot while git runs on every call. The plan keeps Python's exact queries and measures both cases. If the cited-file case misses the budget, the hand-over reports it with the option recorded in `improvements.md` ("Remember git answers per repository state"): memoise git answers keyed by the repository state (`HEAD`, the ref it names, `packed-refs`), which changes churn near the 30-day boundary by up to the memo's lifetime and is therefore a contract change.
2. Nothing else. Every other difference below is either already decided by the spec ("Errors": `isError: true`, corrupt lines skipped) or does not change a tool reply.

## What Python does, precisely

Read from `src/dejafix/{mcp_server,resolver,session_start,search,global_memory}.py`, `src/dejafix/commands/{brief,score,context,global_cmd}.py` and `cli.py` at `778d401`, and from a live `tools/list` of `python -m dejafix.mcp_server` (mcp 2.3.0).

**Start-up.** `_PROJECT_ROOT`: the value after `--root` anywhere in `argv` (`expanduser().resolve()`), else `$DEJAFIX_ROOT` (non-empty, same), else `discover_mem_dir()` from the working directory (walk up, initialised projects only) → its parent, else none. A pinned root `chdir`s there. `GLOBAL_MODE = _PROJECT_ROOT is None`. Server name `dejafix`, version `""`; capabilities `prompts`, `resources`, `tools` (all `listChanged: false`). `instructions` is the fixed text in `mcp_server.py:200-241`, plus `_GLOBAL_INSTRUCTIONS` (`:180-196`) in global mode.

**Tools.** 19, in this order: `start_session`, `get_instructions`, `get_summary`, `get_project_map`, `get_plan`, `precheck_file`, `precheck_files`, `get_issue`, `search_events`, `get_score`, `get_context`, `get_global_gotchas`, `log_issue`, `record_attempt`, `record_fix`, `add_decision`, `add_note`, `list_projects`, `current_project`. Each tool's `description` is its docstring after `inspect.cleandoc`; `inputSchema` is pydantic's (`title` `"{name}Arguments"`, per-property `title` from the name in Title Case, `anyOf [string, null]` with `default: null` for optional strings, `default`, `minimum`/`maximum`, `pattern`, `items`, `required` only when non-empty); `outputSchema` is `{"properties": {"result": {"title": "Result", "type": "string"}}, "required": ["result"], "type": "object", "title": "{name}Output"}`. Every reply is one text block plus `structuredContent: {"result": text}`, `isError: false`, including the tool's own errors.

**Errors.** `safe_tool` turns every exception into the reply `dejafix tool error: {ExceptionClass}: {message}`. Classes that reach it: `ResolutionError` (resolution), `DejafixError` (validation, several open issues, unknown issue, unknown event reference), `FileNotFoundError` (`[Errno 2] No such file or directory: '{path}'`, e.g. `get_score` without `events.jsonl`). Invalid arguments never reach the tool: the SDK replies `Error executing tool {name}: {pydantic message}` with `isError: true`; an unknown tool is `Unknown tool: {name}`, `isError: true`. Unknown argument names are ignored; pydantic's lax mode turns `"5"` into `5`.

**Resolution** (`resolver.resolve(explicit, pinned)`, the server never passes client roots): pinned → must hold `.dejafix/` (`--root {pinned} has no .dejafix/ — run \`djf init\` there first.`); name = registry record's name or the folder name; an explicit argument naming another project → `This server is pinned to '{name}' ({pinned}) and cannot write to '{explicit}'. Start dejafix without --root to serve several projects, or use that project's own server.`; source `pinned`. Explicit → registry `find` (id, alias, path) → record must hold `.dejafix/` (`'{name}' is registered at {path}, but that folder has no .dejafix/ any more. Run \`djf init\` there, or \`djf project remove {name}\`.`), source `explicit`; else an existing directory (`expanduser`) → must hold `.dejafix/` (`{candidate} has no .dejafix/ — run \`djf init\` there first.`), root resolved, name the folder name; else `No project '{explicit}' — not a registered id, alias, or path. Registered: {names or "none registered"}`. Client roots (not used by the server; the resolver supports them): exactly one initialised → `roots`; several → `Your client offered several dejafix projects ({names}). Pass project="<name>" on the call so the write lands in the right one.`. Active project → `_from_record(active, "active")`. Working directory walk-up → `cwd`. Exactly one registered project → `only`. Else `No project selected. Pass project="<name>", or run \`djf project use <name>\` to set an active one. Registered: {names}`. Resolution happens on every call and is never cached.

**Read tools.** `get_instructions`/`get_summary`/`get_project_map`/`get_plan` read `AI_INSTRUCTIONS.md`/`summary.md`/`PROJECT_MAP.md`/`plan.md` as UTF-8 text (universal newlines) or reply `No instructions found. Run \`djf init\` first.` / `No summary found. Run \`djf init\` first.` / `No project map found.` / `No plan found.`. `start_session`: the non-empty of [`SESSION_START_DONE`, instructions, summary, `current_plan(plan)`, `placeholder_map(map)`, `MAP_POINTER`] joined by a blank line; each file stripped; `current_plan` keeps the `## ` sections (split on `"\n## "` after prefixing `"\n"`) whose first line, stripped, is non-empty and not `Ideas`, `Someday / maybe` or `Shipped`, each as `## {section.strip()}`, joined by a blank line; `placeholder_map` keeps the map only when `looks_like_placeholder`. `get_issue`: `normalize_issue_id`, then `[\w-]+` full match or `No issue found with ID {issue_id}.`; the first `issues/{wanted}-*.md` (directory order) or the same reply. `search_events`: casefolded substring over summary, notes, location and files; the last `limit` matches; none → `No events match '{query}'.`; else `Found {n} match(es) for '{query}':` and one `match_line` per match: `  [{type}{ #issue}{ (outcome)}] {id} {timestamp[:10]}: {text}{ @ location}{ (superseded)}`, where the text is the summary, or `{clip(summary)} | notes: {shown}` when the query is only in the notes; `shown` is the whitespace-flattened source, clipped to 300 characters around the match (`excerpt`) unless `full`. `get_score`: `json.loads` of every non-blank line of `events.jsonl`, `calculate_score`, seven lines (`dejafix Prevention Score: {grade} ({score}/100)`, failed approaches, decisions, fixes, `~{hours}h` with Python's float repr, `{tokens:,}`, `${usd:.2f}`). `get_context`: `generate_context(read_events(root), tokens, focus, 30, root)["markdown"]`. `get_global_gotchas`: every gotcha of `~/.dejafix/global/library_gotchas.jsonl`, filtered by a lowercase substring of `library`; none → `No global gotchas found[ for {library}].`; else `Global gotchas ({n}):` and the first 15 as `  [{library or "unknown"}] {gotcha}[ (from {source_project})]`.

**Precheck tools.** `_precheck_report(paths, root)`: M3's `_analyze_files` over all paths at once (churn and staleness from the resolved project's git), warnings grouped by file, then per requested path in order: a memory path → `{path}: this is a dejafix memory file. It is regenerated from the event log, so do not edit it; record the change with add_note / add_decision / log_issue / record_fix instead.`; no warnings → `{path}: no warnings. Safe to modify.`; else `dejafix precheck: {path}` and per warning `  [{SEVERITY}] {title}` and `    - {detail}`; blocks joined by a blank line. The lookup key is `project_relative(path.strip(), root)`, the block shows the path as given.

**Write tools.** `log_issue` → `Logged issue #{id} → {name}`. `record_attempt` → issue = `issue_id` or `sole_open_issue(read_events(root))` (several open → `DejafixError`), `auto_issue=True` → `Recorded {outcome} attempt on #{id} → {name}`. `record_fix` → same issue rule → `Fixed issue #{id} → {name}`. `add_decision` → `Recorded decision {id} → {name}[ (supersedes {old id})]`. `add_note` → `Recorded note {id} → {name}`. Redaction notices and promotion are silent (stdout is swallowed).

**Routing tools.** `list_projects` (no `project` parameter): pinned → `This server is pinned to a single project: {folder name} ({root}).\nThe \`project\` parameter is ignored.`; no projects → `No projects registered. Run \`djf init\` in a repo (it registers automatically), or \`djf project register <path>\`.`; else `ACTIVE: {name} — {path}`, `Calls that omit \`project\` go here. You do not need to pass it.` and a blank line when there is an active project, `{n} project(s) — pass one as \`project\`:`, `  {id}[ / {alias}][ (active)] — {path}` per project, and `\nNo active project: calls that omit \`project\` will fail rather than guess. Set one with \`djf project use <name>\`.` when none is active. `current_project` → `{name} — {root}\nchosen by: {source}`.

**Score** (`calculate_score`): per event `type`, `outcome`, truthy `auto_captured` (auto vs manual), files = `files` + `location_to_file(location)`; every file counts once per event toward `file_event_counts` and `files_with_gotchas`; failed attempts, worked attempts, fixes, decisions, notes. Hours `round(0.5f + 0.25x + 0.15d, 1) + round(0.75 * churn_files, 1)` (churn files have ≥ 4 events); tokens `3000f + 2000x + 500d + 2000auto`; USD `round(tokens / 1e6 * 10, 2)`; components capped at 20 (`min(f*2,20)`, `min(d*1.5,20)`, `min(x*2,20)`, `min(files*0.5,20)`, `min(notes*0.5 + auto*0.3 + worked,20)`), score `min(int(sum),100)`, grades at 90/80/60/40/20.

**Context** (`generate_context`): Task 4 lists every constant and section; it reads `git status --porcelain --no-renames` in the project (5 s timeout, failure → no files) and `PROJECT_MAP.md`.

**`djf brief`** (`brief.run`, cwd-relative, no walk-up for the name): header `dejafix brief — {cwd name}`, a 60-wide rule; warnings (failed attempts in 30 days by file, top 4 by count, stable), possibly stale (first 5, then the retire hint; nothing when none), open issues (last 4), recent live decisions (last 5), stack gotchas (last 3 relevant; `g.get("text") or g.get("summary")`, which is empty for real gotcha entries), the score with the week-over-week delta; a closing rule and an empty line. ANSI colour throughout (stripped when not a terminal).

**`djf global [ACTION] [TEXT] [--tag] [--library] [--older-than N] [--confidence C] [--format|-f text|json]`**: `status`, `list`, `add` (with `--library` it becomes `add-gotcha`), `add-gotcha`, `remove`, `export`, `import`, `prune`, `detect`; anything else → `Unknown action: {action}\nAvailable: status, list, add, add-gotcha, remove, export, import, prune, detect`. Texts in `global_cmd.py`; entries written with `json.dumps(sort_keys=True)`; ids `pat_`/`got_` + 12 hex; `created`/`discovered`/`exported_at` as `isoformat()` with `Z`. All exit 0.

## Decisions a reviewer may question

1. **`isError: true` for the tools' own errors.** The spec ("Errors") decided it; Python sends `false`. The text is Python's (`dejafix tool error: {Class}: {message}`), so an agent reads the same words. The golden tests compare the text and pin the flag.
2. **Invalid arguments get Rust's message.** pydantic's messages (`1 validation error for …`) cannot be reproduced. Rust replies `Error executing tool {name}: {serde message}` with `isError: true`, like the SDK does; numbers given as strings are refused instead of coerced. Unknown argument names are ignored, as in Python.
3. **Schemas are written by hand, not derived.** `schemars` would produce `type: ["string", "null"]` and no `title`s; Python's clients see pydantic's shapes. The 19 input schemas are a static table in `mcp/` built with `serde_json`, compared byte for byte (sorted keys) with Python's `tools/list` by the golden test. `schemars` is therefore not added. Arguments are deserialised into typed structs with `serde` (`deny_unknown_fields` off), and the bounds (`limit` 1–100, `tokens` 100–20000, `outcome` pattern) are checked by the same table.
4. **`initialize` differs where it does not reach the agent.** Server name `dejafix` and the same `instructions`; version is the crate version instead of `""`; only the `tools` capability is advertised (Python also advertises empty prompts and resources). The golden test compares `instructions` and the tool list, not the server info.
5. **Corrupt log lines are skipped, as everywhere in Rust** (spec, "Errors"). Python's `read_events` raises `Invalid event at …` and every read tool fails until the line is fixed; `get_score` still reads raw lines and refuses a line that is not JSON, as Python does (`JSONDecodeError`), but with serde's message.
6. **The cache holds an owned `EventLog`.** `EventLog<'a>` borrows the file's bytes. The cache stores `Arc<Cached { bytes: Arc<[u8]>, log: EventLog<'static> }>`, made by a new `EventLog::into_owned` (every `Cow` becomes owned; `Extra` keeps `Cow<RawValue>` instead of `&RawValue`). No `unsafe`, no self-referential crate, one extra copy per reload. Key: the canonical root; validity: `(len, mtime)` of `events.jsonl` from one `stat` per call. At most 16 projects are cached (least recently used dropped). A write through the server invalidates the entry by changing both.
7. **Writes do not use the cache.** `wiring::record` reads the log under the lock, as the CLI does. The issue an attempt or fix attaches to when `issue_id` is omitted is decided under that lock (the M2 `sole_open_issue` rule), so two servers cannot interleave between the check and the write; Python checks before taking the lock.
8. **Tool bodies run on the blocking pool.** The runtime is `tokio` current-thread; each call runs in `spawn_blocking`, so independent calls run in parallel as in Python's thread pool and a slow git query never stalls the transport. `stdio_pipes()` when both standard streams are pipes, otherwise `stdio()` (spec).
9. **Exception classes are mapped, not inherited.** `ResolveError` → `ResolutionError`; `ValidationError` and a missing project directory → `DejafixError`; an I/O error → `FileNotFoundError`/`PermissionError`/`IsADirectoryError`/`OSError` by `io::ErrorKind` with `[Errno N] {strerror}: '{path}'` where Python would produce it (missing `events.jsonl`, unreadable issue file); other I/O messages are Rust's.
10. **`get_issue` takes the lexicographically first match.** Python takes the first `glob` hit in directory order, which is unspecified when two files share an id prefix (it cannot happen with files dejafix writes).
11. **`brief` and `global` write UTF-8 and colour only on a terminal** (M3 decisions 7 and 8): Python's cp1252 fallbacks are not ported; piped output is byte-identical.
12. **`global import` reports serde's parse error text** after `Invalid JSON: ` (Python prints the `json` module's message). Valid files behave identically.
13. **Reads follow symlinks inside `.dejafix/`, as Python does.** Hardening this is logged in `improvements.md`, not done.

# Rust M5 — `migrate`, `doctor --online`, release configuration — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `djf migrate` carries a projectmem install over to dejafix exactly as Python 0.4.x does (dry run by default, `--apply`, `--path`, resumable steps, atomic rewrites, symlinked memory folders and a live watcher left alone, stale client configs reported). `djf doctor --online` asks PyPI for the newest release and `--auto/--no-auto` remembers a daily check, with Python's texts and meta keys. The repository can build release `1.0.0-rc.1`: `dist` (GitHub Releases, shell and PowerShell installers, Homebrew tap `bigfree/homebrew-tap`), `maturin` (PyPI wheel `dejafix`, trusted publishing) and one GitHub Actions workflow that runs `cargo nextest` on macOS, Linux and Windows before anything is built. Nothing is pushed, tagged or published; the user does that.

**Architecture:** The pure parts of `migrate` (the two marked blocks, the `.projectmem` path rewrite, the stale-config tokens, the step list) live in `core/migrate/`. The filesystem parts (walking a memory folder without following symlinks, the home move with a cross-device fallback, the atomic rewrite that keeps the file mode, the watcher's pid check) live in `adapters/fs/legacy/`. `wiring/setup/migrate.rs` composes them with M2's instruction refresh and bridge writer and M3's hook installer, and reports progress through a callback so the CLI prints each line as Python does, before a later step can fail. The update check is pure version logic in `core/doctor/version.rs`, an HTTPS GET in `adapters/http/`, and the meta bookkeeping in `wiring/setup/update.rs`; the CLI injects the fetch so tests never touch the network. Release configuration is data: `dist-workspace.toml` at the repository root (the Cargo workspace is in `rust/`), `rust/crates/dejafix/pyproject.toml` for maturin, and `.github/workflows/{release,test}.yml`.

**Tech Stack:** Rust 1.99.1 (edition 2024). New dependency, pinned exactly to the latest stable release: `ureq` 3.5.2 (`default-features = false`, features `rustls` and `platform-verifier`). Release tools, installed into `~/.cargo/bin` with `cargo install --locked`: `cargo-dist` 0.34.0 (`dist`), `maturin` 1.16.0. Python 3.15.2 with dejafix 0.4.0 from `src/` as the oracle; git 2.56.

## What Python does, precisely

Read from `src/dejafix/commands/{migrate,doctor,hooks,init,watch}.py`, `project_registry.py`, `storage.py` and `cli.py` at `8baa546`.

**`djf migrate [--apply] [--path/-p PATH]…`** (`migrate.run`). `old_home = ~/.projectmem`, `new_home = DEJAFIX_HOME or ~/.dejafix`.

1. *Projects.* The legacy registry is `old_home/projects.json` when it exists, else `new_home/projects.json`. With `--apply` (or when the file is missing) `load_registry` reads it in place, repairing and saving it as it always does; a dry run loads a throw-away copy (with its `.meta.json`), so nothing is written. Each record gives `(name, path)`. Every `--path` is `Path.resolve()`d (relative to the working directory, no `~` expansion) and added as `(slugify(folder name), path)` unless a registered project already resolves to it.
2. *Banner.* `--apply`: `Close running agent sessions (Claude Code, Codex, Cursor, Claude Desktop) first: a projectmem server still running writes to the old folders.` and a blank line; dry run: `Dry run — nothing is changed. Re-run with --apply to migrate.` and a blank line.
3. *Home.* No `old_home` directory → `Home: {old_home} not found, nothing to move.`. Else `Home: {old_home} -> {new_home}`; with `--apply` `new_home` is created. `in_use` = `new_home/projects.json` exists. For each entry of `old_home` in sorted order: `dest = new_home/name`; the stamp case is `not in_use and name == "projects.meta.json"`; if `dest` exists, holds a file (`is_file()` or any file below it) and is not the stamp → `  skip {name}: {dest} already has data, merge it by hand`; otherwise `  move {name}` and, with `--apply`, an existing `dest` (an empty directory tree or the stamp) is removed and the entry moved (`shutil.move`: rename, or copy and delete across file systems). With `--apply`, an `old_home` left empty is removed.
4. *Each project*, label `Project {name} ({root})`, `legacy = root/.projectmem`, `target = root/.dejafix`, checked in this order: either is a symlink → `{label}: the memory folder is a symlink, migrate it by hand.`; `legacy` is a directory and `target` exists → `{label}: both .projectmem/ and .dejafix/ exist, merge them by hand.`; neither `legacy` nor a `target` directory → `{label}: no .projectmem/ found, skipped.`; `legacy/watch.pid` holds an integer pid of a live process → `{label}: the old watcher (pid {pid}) is still running. Stop it with \`pjm watch --stop\` in that project, then re-run.`. Then the steps, each only when needed: `rename .projectmem/ -> .dejafix/`; `update .projectmem paths recorded in {n} memory files` (files below the memory folder, not symlinks, suffix `.md .jsonl .json .toml .bak`, UTF-8, matching `\.projectmem\b`); `refresh AI_INSTRUCTIONS.md (previous copy kept as .bak)` (marker version below 3); `update .gitignore entries` (`.gitignore` matches `\.projectmem\b`); `replace the bridge block in {CLAUDE.md, AGENTS.md}` (files holding `<!-- >>> projectmem bridge >>> -->`); `reinstall git hooks: {names}` (`post-commit`, `post-merge`, `pre-commit` under `root/.git/hooks` holding `# >>> projectmem auto-capture >>>`). No step → `{label}: already migrated.`; else `{label}:` and `  {step}` per step. With `--apply`, in this order: rename; rewrite each listed file (`.projectmem` → `.dejafix`, read as UTF-8 text with universal newlines, written atomically with the old mode, no newline translation on write); rewrite `.gitignore`; refresh the instructions (M2's `refresh_ai_instructions`, which also adds `.dejafix/AI_INSTRUCTIONS.md.bak` to `.gitignore`); convert each bridge block (rename the markers, or drop every old block when a dejafix block is already there) and run `_ensure_claude_md(root, name)` (prints `  {file}: created with dejafix bridge.` / `dejafix bridge appended.` / `dejafix bridge refreshed.`); convert each hook block the same way and run `install_hooks` (prints M3's install summary).
5. *Leftovers.* Files: every client config of `_client_configs()` (no project configs), `~/.claude/settings.json` (`Claude Code hooks`), `~/.codex/hooks.json` (`Codex hooks`); a file is stale when its UTF-8 text holds one of `projectmem.mcp_server`, `mcp_servers.projectmem`, `"projectmem":`, `pjm-mcp`, `pjm-edit-hook`, `PJM_EDIT_HOOK_LOG`, `PROJECTMEM_`. Variables: names starting `PROJECTMEM_` or `PJM_`, sorted. When any: a blank line, `Still pointing at projectmem — update these by hand:`, `  {client}: {path}` per file, `  environment variable {name}` per variable, and the fixed MCP/edit-hook hint.
6. *Done* (`--apply` only): a blank line and `Done. Commit the renamed .dejafix/ folder in each project, and uninstall projectmem once your clients point at dejafix.`. Exit 0 throughout.

**`djf doctor --online` / `--auto` / `--no-auto`.** `--auto`/`--no-auto` first stores `update_check: true/false` in `projects.meta.json` and prints `✓ Automatic update checks on (once a day)` / `… off` and a blank line (green). The version block replaces M2's offline block: when neither `--online` nor `update_check` → M2's text. Otherwise `newest = meta.update_latest`; with `--online`, or when `now − update_checked_at > 86400 s`, `latest_version()` (GET `https://pypi.org/pypi/dejafix/json`, header `User-Agent: dejafix/{version}`, 3 s timeout, `info.version`, any failure → none) and, on success, `update_checked_at = time.time()` and `update_latest` are saved. No version → `✓ Running {v}` and `      Could not reach PyPI — nothing else was affected.`; `_as_tuple(newest) > _as_tuple(v)` (the first three dot-separated chunks, each its leading digits or 0, compared as tuples) → `⚠ {newest} is available (you have {v})` (yellow) and `      pip install -U dejafix`; else `✓ Running {v} — the latest`.

## Decisions a reviewer may question

1. **Progress through a callback.** Python prints as it goes and a failing step leaves the earlier lines on screen. `wiring::migrate` takes `&mut impl FnMut(MigrateEvent)`; the CLI renders each event at once. An I/O error stops the run (spec "Errors": `Error: …`, exit 3); everything done before it stays done, and the next run resumes, as in Python.
2. **No symlink is followed or deleted by the home move.** Python's `_holds_files` follows a symlinked `dest`, and its `rmtree` raises on one. Rust treats any `dest` that is a symlink (live or broken) as data and prints Python's `skip … merge it by hand` line. Only the crash cases change.
3. **Memory folders are walked without following symlinks** (Python 3.13's `rglob` does the same); symlinked files are never rewritten. Rewrites go through the existing `write_atomic` (temporary file in the same directory, old permissions, rename), so a crash leaves either the old or the new file.
4. **Universal newlines on read, `\n` on write**, as Python's `_read`/`_write_atomic` do. On Windows this turns a CRLF memory file into LF, exactly as Python does; logged in `improvements.md` as an idea, not changed.
5. **The watcher check** uses `rustix::process::test_kill_process` on Unix (`EPERM` counts as alive, as Python's `PermissionError`) and `tasklist /FI "PID eq N" /NH /FO CSV` on Windows (no `unsafe`, no new crate). A pid of 0 or below is not a watcher (Python's `os.kill(0, 0)` would call it alive; a real `watch.pid` never holds it).
6. **Cross-device moves.** `fs::rename`, and on `CrossesDevices` a copy that recreates symlinks as symlinks, followed by removing the source, like `shutil.move`.
7. **The update check never blocks longer than 3 s** (`ureq` global timeout) and honours `HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY` (ureq reads them, as `urllib` does). Certificates come from the operating system's trust store (`platform-verifier`), which matches `urllib` on Windows and on most macOS and Linux Pythons and works behind corporate TLS inspection where a bundled root list would not.
8. **`update_checked_at` is written as a Python float** (seconds with microseconds, Python `repr`), so a Python 0.4.x `doctor` reads it, and Rust reads Python's.
9. **One workflow file, hand-edited after `dist` generates it.** PyPI's trusted publishing does not support reusable workflows (PyPI troubleshooting docs; `gh-action-pypi-publish` warns), so the PyPI upload must be a job of `release.yml` itself, which `dist` cannot generate. `dist-workspace.toml` sets `allow-dirty = ["ci"]`; the edits are listed in a header comment of `release.yml` and below: least-privilege `permissions` (read at the top, `contents: write` only for `host` and `announce`), the `test` job inline (no inherited secrets) and required by every build, the `build-wheels` matrix and the `publish-pypi` job (environment `pypi`, `id-token: write` only there). Action references are pinned to full commit SHAs through `github-action-commits`.
10. **The tests run in a reusable `test.yml`** called by `release.yml` and runnable by hand (`workflow_dispatch`), so Windows can be checked before a tag exists. It installs Python and dejafix 0.4 from `src/` for the golden tests.
11. **`publish-prereleases = true`**, so `1.0.0-rc.1` reaches the tap and PyPI (pip skips pre-releases unless asked, Homebrew users of the tap get the rc, which is the point of the rc period).
12. **The maturin `pyproject.toml` lives next to the binary crate** (`rust/crates/dejafix/`), because the repository root's `pyproject.toml` is the Python 0.4.x package until M6. Its version is dynamic (Cargo's `1.0.0-rc.1` becomes `1.0.0rc1`).
13. **The tests' `0.0.0` expectations** become `CARGO_PKG_VERSION` where they named the version literally.

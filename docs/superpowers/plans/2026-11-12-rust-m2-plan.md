# Rust M2 — write path, summary, global memory, registry and the CLI — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Rust binary `djf` records issues, attempts, fixes, decisions and notes exactly as Python 0.4.x does (same `events.jsonl` lines, `summary.md`, `issues/*.md`, current-issue marker, global memory files, registry files and terminal output), initialises a project with the same files, and offers `init`, `log`, `attempt`, `fix`, `decision`, `note`, `show`, `search`, `regenerate`, `project`, `doctor`, `instructions`, `plan` and `map`.

**Architecture:** Every decision is pure and lives in `core/`: redaction, building new events and resolving their issue, rendering `summary.md` and the issue files, search, lesson promotion, the instruction and initial-file templates, and the registry model. `adapters/fs` does the I/O: finding `.dejafix/`, appending under `File::lock`, atomic rewrites, the marker, the global store, stack detection, registry files, project scans and client-config discovery; `adapters/git` reads the short `HEAD`. `wiring/` composes them into one function per command, returning a typed outcome. The binary crate parses arguments with clap, reads the environment once in `config/`, prints outcomes and maps errors to exit codes. Python stays the oracle: golden tests run Python from `src/` and the Rust binary on copies of one fixture and compare outputs and files byte for byte.

**Tech Stack:** Rust 1.99.1 (edition 2024); existing: serde 1.0.229, serde_json 1.0.154 (features `float_roundtrip`, `raw_value`, new: `preserve_order`), jiff 0.2.43, regex 1.13.1, thiserror 2.0.21, sha1 0.11.0, tempfile 3.27.0 (now also a regular dependency); new: clap 4.6.7 (feature `derive`), getrandom 0.4.3; new dev-only: insta 1.49.0, assert_cmd 2.2.2. Python 3.15.2 with dejafix 0.4.0 from `src/` as the oracle.

## Global Constraints

Copied from `docs/superpowers/specs/2026-11-12-rust-rewrite-design.md` ("Code rules", "Data flow", "Errors", "Compatibility contract", "Testing") and `CLAUDE.md`:

- No comments and no `///` doc comments. Only `TODO(#issue)` and tool directives such as `#[expect(lint, reason = "...")]`.
- Types live in the module's `types.rs`; behaviour lives in sibling files.
- `[workspace.lints]`: `unsafe_code = "forbid"`; clippy `pedantic`; `unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `indexing_slicing`, `as_conversions`, `allow_attributes` denied outside tests. Lint exceptions use `#[expect]`, never `#[allow]`.
- Errors are typed `thiserror` enums per domain (`ValidationError`, `StoreError`, `RegistryError`, `ParseError`, `ResolveError`). No `anyhow`.
- `core` never imports `adapters` or `wiring`. What it needs from I/O it declares as a trait or takes as an argument.
- At most 12 source files per directory. Unit tests next to the code in `tests.rs`; integration tests in the crate's `tests/`.
- Performance is part of correctness: no allocation, copy or re-parse inside a loop that can happen once outside it.
- Current Rust only: let-chains, `LazyLock`/`OnceLock`, iterator adapters instead of intermediate vectors, `std::env::home_dir`, `File::lock`.
- Before using any API of Rust or a dependency, check its documentation through Context7 at the pinned version, not from memory. Each task lists its "Context7 checks".
- Dependencies: latest stable, pinned exactly (`=x.y.z`), widely used, standard library first.
- Only `config/` (binary crate) reads environment variables (`DEJAFIX_HOME`, `DEJAFIX_NO_REDACT`, `HOME` through `std::env::home_dir`, and for client-config discovery `XDG_CONFIG_HOME`, `APPDATA`, `LOCALAPPDATA`). The library receives values as arguments.
- Write path (spec, "Data flow"): validate and redact; append one line to `events.jsonl` under `File::lock`; apply the event to the loaded `EventLog` without re-parsing; rewrite `summary.md` and the issue files atomically, update the marker, promote the lesson.
- CLI errors (spec, "Errors"): message on stderr, exit 1 for a user error, 2 for bad arguments (clap), 3 for I/O. A corrupt log line is skipped and counted; `djf doctor` reports it; the log is never rewritten.
- Data format unchanged: for the same input, Rust output is byte-identical to Python 0.4.x, except the deliberate differences listed under "Decisions".
- `just verify` runs fmt, clippy, nextest and the coverage gate (90 % lines in `dejafix-core`, 80 % in `dejafix`). `just golden` runs the golden tests. The `summary.md` regeneration budget is ≤ 30 ms at 3,000 events.
- Commits: `type(scope): imperative lowercase subject`, body explains why, no assistant attribution of any kind (no `Co-Authored-By`, no "Generated with"). Commit after the reviews from `CLAUDE.md`, on branch `claude/rust-m2-45290e`; no push, PR or merge without asking.

## What Python does, precisely

Read from `src/dejafix/{storage,summary,redaction,models,search,global_memory,project_registry,glyphs,cli}.py` and `commands/{init,log,attempt,fix,decision,note,show,search,plan,map,instructions,regenerate,project,doctor}.py`. Line numbers are of the files at commit `e5ddca3`.

**Finding the memory directory** (`storage.require_mem_dir`): `Path.cwd()/.dejafix` if it is a directory containing `config.toml`; else the first of `cwd.resolve()` and its parents whose `.dejafix/` contains `config.toml`; else `DejafixError("No .dejafix directory found in {cwd} or any parent. If running over MCP, set the project root via the `cwd` field in your MCP client config or via the DEJAFIX_ROOT environment variable. Otherwise run `dejafix init` to create one.")`. The CLI never passes a root, so every command uses this.

**New event** (`models.Event`): `id = "evt_" + uuid4().hex[:20]`, `timestamp = utc_now_iso()` (`%Y-%m-%dT%H:%M:%SZ`), `summary` stripped (Python `str.strip`) and non-empty or `ValueError("Event summary cannot be empty")`; written as `json.dumps(event.to_dict(), sort_keys=True) + "\n"` (the M1 encoder: falsy fields dropped, `""` kept).

**Redaction** (`redaction.py`): unless `DEJAFIX_NO_REDACT.strip()` ∈ {`1`, `true`, `yes`}, each of `summary`, `notes`, `command`, `git_message`, `location` that is a non-empty string runs through ten patterns in order, each `re.sub` over the previous output, replacing a match with `[REDACTED:<kind>]`:

| kind | pattern |
|---|---|
| `openai_key` | `\bsk-[A-Za-z0-9_-]{40,}\b` |
| `github_pat` | `\bgithub_pat_[A-Za-z0-9_]{82}\b` |
| `github_token` | `\bgh[pousr]_[A-Za-z0-9]{36}\b` |
| `aws_access_key` | `\bAKIA[0-9A-Z]{16}\b` |
| `google_api_key` | `\bAIza[0-9A-Za-z_-]{35}\b` |
| `slack_token` | `\bxox[abprs]-[A-Za-z0-9-]{10,}\b` |
| `stripe_key` | `\b(?:sk\|pk\|rk)_(?:live\|test)_[A-Za-z0-9]{24,}\b` |
| `jwt` | `\beyJ[A-Za-z0-9_-]{8,}\.eyJ[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{10,}\b` |
| `bearer_token` | `(?<![A-Za-z])[Bb]earer\s+[A-Za-z0-9._~+/=\-]{20,}` |
| `private_key` | `-----BEGIN [A-Z ]*PRIVATE KEY-----` |

When anything fired: stderr `dejafix: redacted {n} secret(s) before write ({sorted unique kinds joined by ", "})`. A redaction failure never blocks the write.

**Append** (`storage.append_event`): redact, append the line (no lock), then for `attempt`/`decision`/`note`: `stack = detect_stack(cwd)` (side effect: `.promotable.json`), `auto_promote_event(summary, type, cwd.name, libraries + tags, outcome)`; any exception there is swallowed.

**Issue bookkeeping** (`storage.py:697-834`): `next_issue_id` = 1 + max of `int(issue_id)` over issue events whose `issue_id.isdigit()`, formatted `%04d`. `current_issue_id` = `issue_id` of the last issue event whose `issue_id` is not closed. `open_issue_ids` = newest-first, deduplicated issue ids not closed. `sole_open_issue` raises `"{n} issues are open, so pass issue_id (the id log_issue returned). Open issues, newest first: #a, #b{ and k more}."` (first 10). Marker `.dejafix/.current_issue`: written as the bare id (no newline), read `strip()`ped, empty → none; `active_issue_marker` clears a marker naming no issue event. `latest_open_issue_within(5)`: the most recent issue event not closed; if its timestamp (`fromisoformat`) is ≥ now − 5 min, its id; else (or unparsable) none.

**Commands** (exact messages):

- `log TEXT [--at L]`: `next_issue_id`; issue event with `git_commit` and `location`; marker := id; regenerate; stdout `Logged issue #{id}`.
- `attempt TEXT [--worked|--failed|--partial] [--at L] [--issue I] [--auto-issue]`: two outcome flags → `Use only one of --worked, --failed, or --partial.`; `--issue`: normalised, must name an issue event, else `Issue #{normalised or I.strip().lstrip('#') or '?'} was not found. Run `djf search <query>` or `djf brief` to find the issue ID.`; otherwise marker, else `latest_open_issue_within(5)`; none and no `--auto-issue` → `No active issue. Run `djf log "<summary>"` first, pass `--issue <id>` to attach explicitly, or rerun with `--auto-issue` to auto-create a parent issue from this attempt's text.`; with `--auto-issue`: append an issue event (same text, location), marker := new id. Outcome defaults to `partial`. Regenerate; stdout `Recorded {outcome} attempt on #{id}`.
- `fix TEXT [--at L] [--issue I]`: `requested = normalize(I)`; `active = marker or current_issue_id`; requested must exist (`Issue #{requested} was not found. …` as above); none at all → `No open issue found. Run `djf log <text>` first.`; append; clear marker when `requested is None or active == issue`; regenerate; `Fixed issue #{id}`.
- `decision TEXT [--at L] [--supersedes REF]`: resolve REF first (M1 `resolve_event_ref`, errors go to stderr as `Error: {message}`, exit 1, nothing written); append with `supersedes = id`; regenerate; `Recorded decision (supersedes {id}: "{summary[:60]}")` or `Recorded decision`.
- `note TEXT [--at L]`: append; regenerate; `Recorded note`.
- `show`: prints `summary.md` followed by a newline (`typer.echo` adds one).
- `search QUERY [--regex|-r] [--failed-only]`: see "Search" below.
- `regenerate`: `Regenerated {summary path}`.
- Every `DejafixError` → stderr `Error: {message}`, exit 1.

**Summary** (`summary.py`): see Task A6 for the full algorithm; constants `RECENT_FIXED_ISSUES = 10`, `RECENT_DECISIONS = 15`, `OPEN_IN_FULL = 20`, notes last 10, key files first 20, `RECORD_CHARS = 300`. The project purpose comes from `PROJECT_MAP.md` `## Project purpose`, else the existing `summary.md`, else the placeholder. Issue files `issues/{issue_id}-{slug}.md` for every group that has an issue event, rewritten every time.

**Search** (`search.py`, `commands/search.py`): substring mode compares `query.casefold()` with `summary`, `notes`, `location` and each of `files` casefolded; `--regex` compiles `re.compile(query, re.IGNORECASE)` and on `re.error` falls back to substring. `--failed-only` keeps failed attempts. No match: `No matches. (Tip: substring match is the default — rerun with `--regex` if you intended an OR/regex pattern.)` when not regex and the query has one of `|*?+()[]\`, else `No matches.`. Each match: `{timestamp} [{id}] {type}{ #issue}{ (outcome)}: {summary}{ (superseded)}`.

**Global memory** (`global_memory.py`): directory `$DEJAFIX_HOME/global` or `~/.dejafix/global`, created on every access. Stack detection reads 16 manifests (Task A8 lists them) and returns sorted `tags`, `libraries`, `frameworks` and `manifest_files` in detector order; it then merges `libraries + tags` into `.promotable.json` (`json.dumps({"libraries": sorted}, sort_keys=True, indent=2)`, no trailing newline) when that adds anything. Promotion and inheritance: Tasks A8 and B2.

**Registry** (`project_registry.py`): `projects.json` is a JSON list of absolute path strings, `projects.meta.json` the sidecar; both written with `json.dump(payload, indent=1)` + `"\n"` through a `.pm-*.json` temp file and `os.replace`. Task B3 has the details.

## Decisions a reviewer may question

1. **One lock for the whole command.** `events.jsonl` is opened `read + append`, `lock()`ed, read and parsed, the new events are appended, `summary.md`, the issue files and the marker are rewritten, and only then is the file closed. Two Rust writers therefore never interleave and the summary always reflects the full log. Python writers take no lock; mixing the two is no worse than Python alone. Plain readers (`show`, `search`, the M1 `read_events_file`) take `lock_shared`, because on Windows `LockFileEx` is mandatory and an unlocked read during a write would fail instead of waiting.
2. **Atomic rewrites keep the file's mode.** An existing file is replaced through `tempfile::Builder::new().prefix(".djf-").tempfile_in(dir)` + `persist`, after copying the old file's permissions onto the temp file (a temp file is `0600`, Python's `write_text` leaves `0644`). A file that does not exist yet is created directly with `File::create_new`, so its mode follows the umask as in Python. Registry files keep Python's `.pm-` prefix and `0600`, as `mkstemp` gives.
3. **Unchanged issue files are not rewritten.** Python rewrites every `issues/*.md` on every write; Rust compares with the file on disk first. Contents are identical either way; this is what keeps regeneration within 30 ms on 3,000 events and keeps a write from touching hundreds of files.
4. **Issue files with an unsafe name are skipped.** Python writes `issues/{issue_id}-{slug}.md` with the raw `issue_id` of a log line, so a hand-edited or hostile log with `issue_id` `../../x` writes outside `.dejafix/`. Rust writes an issue file only when the id is a single normal path component (no `/`, `\`, NUL, `.` or `..`, no drive prefix). The summary still lists the issue.
5. **The project root, not the working directory, names the summary.** Python's `build_summary` and promotion use `Path.cwd().name`, so running `djf log` from a subdirectory titles `summary.md` with the subdirectory's name and credits the lesson to it. Rust uses the root that holds `.dejafix/`. Identical whenever `djf` runs at the root, which is the only case the golden tests and nearly every user exercise.
6. **Tie order in "Key files" is first mention, not Python's.** Python counts paths per event through a `set`, so paths first seen in the same event enter the ranking in hash order, which `PYTHONHASHSEED` randomises per process. There is no deterministic Python output to match. Rust ranks by count, then by first mention (files, location, then text mentions, in order). The golden comparison canonicalises the "Key files" section (Task A12) and a separate golden test checks the counts against Python.
7. **Python regular-expression features the `regex` crate lacks are emulated where Python's patterns use them and documented where users supply them.** The two fixed lookbehinds (`bearer_token`, file mentions) are checked in code with Python's retry-at-next-position semantics. Python's `\w`, `\s` and `\d` are written out as explicit classes (`[\p{L}\p{N}_]`, Python's `str.isspace` set, `\p{Nd}`). `\b` keeps the crate's Unicode definition, which differs from Python's only next to combining marks, `No` digits and connector punctuation other than `_`; the redaction corpus and proptest cover ASCII and the other categories. A `--regex` query using backreferences or lookaround fails to compile in Rust and falls back to substring search, as Python does for its own syntax errors.
8. **`casefold` is a generated table.** Rust has no full case folding. `core/text/casefold_table.rs` is generated from Python 3.15 (`chr(c).casefold()` for every code point where it differs) by `rust/scripts/casefold.py` and checked by a golden test over all 1,114,112 code points.
9. **Errors are messages, not tracebacks.** Where Python lets an exception escape (empty summary → `ValueError`, missing `summary.md` → `FileNotFoundError`), Rust prints `Error: …` and exits 1 (user error) or 3 (I/O). Where Python already prints a message, the text is identical.
10. **Random ids keep Python's shape.** `evt_` + the first 20 hex digits of a version-4 UUID (digit 12 is `4`, digit 16 is `8`–`b`), from 16 bytes of `getrandom::fill` with the UUID version and variant bits set. Global entries use `pat_`/`got_` + 12 hex digits. Unit tests inject ids through the `Ids` trait; production uses `OsIds`.
11. **`serde_json` gains `preserve_order`.** `projects.meta.json` and `doctor-state.json` are rewritten from a loaded dict in Python, keeping key order. With `preserve_order`, `serde_json::Map` keeps insertion order too. M1 never relied on map order: `write_canonical` sorts explicitly.
12. **`EventLog::push` applies a new event to every index.** The CLI only needs `events()` after a write, but the MCP cache (M4) will reuse `push`. A proptest checks that parsing a prefix and pushing the rest gives the same answers as parsing everything.
13. **The MCP config block printed by `init` points at the Rust server.** Python prints `sys.executable -m dejafix.mcp_server`; Rust prints the absolute path of the `djf-mcp` executable next to the running `djf` and no module arguments (Task B6). This is the one deliberate difference in `init` output; the golden scenario passes `--no-mcp-config` and snapshot tests cover the block.
14. **Windows identity for scan deduplication is the canonical path.** Python compares `(st_dev, st_ino)`; Rust's `MetadataExt::volume_serial_number`/`file_index` are unstable on Windows, so there the canonical path (which carries the real case) is the key. Unix uses `(dev, ino)` as Python.
15. **New dependencies:** `clap` (planned), `getrandom` (no stable std randomness), `insta` and `assert_cmd` (planned dev-dependencies), `tempfile` becomes a regular dependency (planned), `serde_json/preserve_order` (adds `indexmap`).

fn replace_with_lookbehind(text: &str, regex: &Regex, kind: SecretKind, fired: &mut Vec<SecretKind>) -> Option<String> {
    let mut out = String::new();
    let mut copied = 0;
    let mut at = 0;
    while let Some(found) = regex.find_at(text, at) {
        let blocked = text.get(..found.start()).and_then(|head| head.chars().next_back()).is_some_and(|c| c.is_ascii_alphabetic());
        if blocked {
            at = found.start() + text.get(found.start()..).and_then(|tail| tail.chars().next()).map_or(1, char::len_utf8);
            continue;

        out.push_str(text.get(copied..found.start())?);
        out.push_str("[REDACTED:");
        out.push_str(kind.as_str());
        out.push(']');
        fired.push(kind);
        copied = found.end();
        at = found.end();
    }
    (copied > 0).then(|| { out.push_str(text.get(copied..).unwrap_or("")); out })
}

fn uuid4_hex() -> String {
    let mut bytes = [0_u8; 16];
    if getrandom::fill(&mut bytes).is_err() {

## Found during implementation

M2a:

- **Python reads and writes every text file in text mode.** `read_text` turns `\r\n` and a lone `\r` into `\n`, and on Windows `write_text` and `open("a")` turn `\n` into `\r\n`. `core/text` gained `universal_newlines` (applied to every text file Rust reads: `PROJECT_MAP.md`, `summary.md`, the marker, manifests, global files) and `platform_newlines` (applied to every text file Rust writes, `events.jsonl` included), so the bytes on disk match Python on Windows too.
- **`serde_json/preserve_order` changed `write_python_json` on a `Value`:** it now keeps insertion order. The fixture generator wrote through it and relied on sorted keys; it now calls `write_canonical`. Event lines were never affected (`Event` sorts its own keys).
- **The regenerate budget:** steady-state `regenerate` at 3,000 events took 42 ms with a sequential check of the issue files (a 3,000-event fixture has several hundred), against 0.9 ms for rendering `summary.md`. Checking the issue files on up to 8 threads (`thread::scope`) brought it to 25.1 ms (criterion mean, 23.3–27.6 ms); 30,000 events take 290 ms. The first regeneration, which writes every issue file, takes 119 ms at 3,000 events.
- **Writes replace symlinks instead of following them.** `write_atomic` renames over the path, so a hostile `.dejafix/summary.md -> ~/.bashrc` link is replaced rather than written through, which Python's `write_text` would do. The marker is written the same way.
- **Python's `\b` and the crate's agree on everything the corpora exercise.** Redaction (2,000 random strings plus every secret shape between 21 neighbours, non-ASCII ones included), stack detection on 12 manifest sets, promotion on 15 summaries, both purpose extractors on 20 texts, and `summary.md` and every issue file of the 100- and 3,000-event fixtures match Python byte for byte. Word characters agree on every code point both Unicode versions assign.
- **`brief`, `djf score` and the Windows `doctor` console row** moved as approved: `test_brief_*` to M4, `test_commands_survive_a_cp1252_console[command0]` (`score`) out of scope.
- **The M0 golden check that ran `show` as a stub** now runs `search`, which reads and leaves the fixture untouched.
- **Reviews of M2a.** Round 1 (`/code-review high`, 10 findings): fixed — `--issue ""` now reads the marker as Python does, git runs before the log is locked, a dangling symlink at a written path is replaced, detection moved out of `stack/mod.rs`, the zone is read in `config/`, one shared text reader, the git poll starts at 0.5 ms, `promotion` returns only the library, `SeqIds` lives in `testing`; skipped — rewriting only the touched issue file (Python heals every issue file on every write; logged in `docs/superpowers/improvements.md`).

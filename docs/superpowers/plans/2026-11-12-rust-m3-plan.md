# Rust M3 — git hooks, precheck, staleness and the edit hook — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Rust binaries install and remove dejafix's git hooks (`djf hooks`, and `djf init` without `--no-hooks`), capture commits and merges into `events.jsonl` (`djf _auto-capture`), warn before a commit (`djf precheck`, including snoozes and staleness), and show a file's lessons right before an agent edits it (`djf-edit-hook`, Claude Code `PreToolUse`/`SessionStart` and Codex `apply_patch`/`PostCompact`), exactly as Python 0.4.x does.

**Architecture:** Every decision stays pure and lives in `core/`: hook snippets and their in-place refresh (`core/hooks`), commit classification and location ranking (`core/capture`), staleness (`core/stale`), the precheck analysis, rendering and snooze arithmetic (`core/precheck`), and the edit hook's tolerant record reader, lesson report, session keys and CRC-32 marker names (`core/lessons`). `adapters/git` gains one process runner with Python's 5 s timeout and detached stdin, the diff and history queries, and the hook files themselves; `adapters/fs` gains the edit hook's per-session markers in the temp directory. `wiring/hooks/` composes them into one function per entry point. The binary crate adds `djf hooks`, `djf _auto-capture` and `djf precheck` in `cli/hooks.rs`, prints the hook lines of `djf init`, and implements `djf-edit-hook` in `hook/`. Python stays the oracle: golden tests run both implementations on copies of one fixture, including real git repositories with fixed commit dates.

**Tech Stack:** Rust 1.99.1 (edition 2024); existing crates only, plus `rustix` 1.1.6 (Unix only, feature `process`, already in the lock file through `tempfile`) for `getuid`. Python 3.15.2 with dejafix 0.4.0 from `src/` as the oracle; git 2.56.

## What Python does, precisely

Read from `src/dejafix/commands/{hooks,auto_capture,precheck,init}.py`, `src/dejafix/{staleness,edit_hook,glyphs}.py` and `cli.py` at the merge base `ca3393d`.

**`djf hooks [ACTION]`** (default `install`): `hooks_dir = cwd/.git/hooks`; missing → stderr `Error: .git/hooks directory not found. Is this a git repository?`, exit 0. `install`/`uninstall`, anything else → stdout `Unknown action: {action}`, exit 0.

**Snippets** (markers `# >>> dejafix auto-capture >>>` / `# <<< dejafix auto-capture <<<`, shebang `#!/bin/sh\n`): post-commit `commit`, post-merge `merge`, pre-commit precheck; texts verbatim from `hooks.py:85-122`. `DJF_BIN` is the resolved binary with `\` replaced by `/`: the `djf` (then `dejafix`) next to the running interpreter if it is a file and executable (Windows: `Scripts/djf.exe`, `Scripts/dejafix.exe`, no executable check), else `which djf`, `which dejafix`, else bare `djf`.

**Sync one hook** (`_sync_hook`): missing file → write shebang + snippet, `chmod +x` (`| 0o111`), `installed`. No start marker → `content.rstrip("\n") + "\n\n" + snippet`, `installed`. Start without end marker → `skipped`. Else replace `[start, end + len(END) (+1 if "\n" follows))` with the snippet; when the first line is `#!/usr/bin/env bash` and nothing but marked blocks remain outside the markers (`re.sub(START.*?END, "", rest, DOTALL).strip()` empty), the shebang becomes `#!/bin/sh`; unchanged → `current`, else write, `refreshed`. Files are read and written in text mode (universal newlines in, platform newlines out).

**Install report:** for each skipped hook, stderr `Warning: .git/hooks/{name} has a dejafix start marker but no end marker, so it was left alone. Fix or delete that block, then re-run `djf hooks install`.`; installed → stdout `dejafix git hooks installed: {names}` plus the two `  Auto-captures: …` / `  Pre-commit: …` lines; refreshed → `dejafix git hooks refreshed: {names}`; nothing at all → `dejafix git hooks already installed.`. Order of names: post-commit, post-merge, pre-commit.

**Uninstall:** for each of the three hooks that exists and contains the start marker: drop every line containing the start marker through the line containing the end marker (line-wise, `split("\n")`), `"\n".join(...).strip()`; empty, `#!/usr/bin/env bash` or `#!/bin/sh` → delete the file, else write `remaining + "\n"`. Report `dejafix hooks removed from: {names}` or `No dejafix hooks found to remove.`.

**`init`:** after the project map step and before global memory: hooks unless `--no-hooks`: `cwd/.git/hooks` exists → install (its output) then `  Auto-capture active — events will be logged automatically.`; else `  Note: No .git directory found. Run `djf hooks install` after `git init`.`.

**`djf _auto-capture [TRIGGER]`** (hidden, default `commit`): nothing unless `cwd/.dejafix` exists; nothing if `.dejafix/config.toml` contains `auto_capture = false`. `commit`: message = `git log -1 --pretty=%B` stripped (none → stop); changes = `git diff-tree -r -M -l1000 -z --name-status HEAD^ HEAD`, on a non-zero exit `git diff-tree --root --no-commit-id … HEAD` (OS error or timeout → no changes), fields split on NUL, status = first letter, `R`/`C` take the next field as the path; location = first of the lowest `_location_rank` among non-deleted, non-memory paths; files = location then the other paths stably sorted with memory paths last, capped at 10; commit = `git rev-parse --short HEAD`; stop if any event's `git_commit` equals it (read failure → carry on); classify (first matching of seven patterns, case-insensitive `search`); stop below `medium`; summary `"{prefix}: {first_line}"` with `first_line = msg.strip().split("\n")[0][:120]`; event `type`, `outcome`, `files`, `git_commit`, `location`, `auto_captured: true`, `capture_source: git_post_commit`, `capture_confidence`, `git_message: first_line`, `command: auto-capture`; `append_event` (redaction, promotion) then `regenerate_summary`; stdout `\033[0;3Xm[dejafix] Auto-captured: {summary}\033[0m` (click strips the escapes when stdout is not a terminal). `merge`: a `note` `Merge: {first_line}`, `capture_source: git_post_merge`, `capture_confidence: high`, no files or location; stdout `[dejafix] Auto-captured merge: {first_line}` in magenta. Any exception while writing is swallowed.

**`djf precheck [FILES]… [--level|-l L] [--working] [--quiet|-q] [--snooze D] [--unsnooze]`**: nothing unless `cwd/.dejafix` exists. `--unsnooze`: remove `.dejafix/precheck.snooze`, `dejafix: precheck warnings re-enabled.` or `dejafix: no active snooze.`. `--snooze D`: `^(\d+)\s*([mhd])$` (case-insensitive, after `strip`), zero → `Snooze duration must be positive.`, no match → `Invalid duration '{D}' — use forms like 30m, 2h, or 1d.` (stderr `Error: …`, exit 1); expiry = now without microseconds + D, written as `isoformat()` (`…+00:00`); a `note` `precheck warnings snoozed for {D} (until {expiry})` appended (redaction, promotion, **no** summary regeneration, failure ignored); stdout `dejafix: precheck warnings snoozed until {HH:MM} UTC (logged to memory). Re-enable early with `djf precheck --unsnooze`.`. An active snooze (unparsable or expired → file removed) prints `\033[2mdejafix: warnings snoozed ({remaining} left) — `djf precheck --unsnooze` to re-enable.\033[0m` and stops; `remaining`: whole minutes, at least 1, `{m}m`, `{h}h{mm}m` or `{h}h`. Files: named, else `git diff --name-only` (`--working`) or `git diff --cached --name-only`, each line stripped. None → `dejafix: No files to check.` unless quiet. Unreadable log → silent. The analysis is `_analyze_files` (Task 6). No warnings → `\033[32mdejafix:\033[0m no warnings — looking good!` unless quiet. Rendering and the block exit: Task 6.

## Decisions a reviewer may question

1. **The edit hook reads events its own way.** Python's edit hook does not use `models.Event`: it reads `events.jsonl` as `utf-8-sig` with `errors="replace"`, splits with `str.splitlines`, keeps every line that is a JSON object, and reads fields through `text_of` (a non-string is `""`). A line with an unknown `type`, `outcome` or `capture_source`, which `EventLog` skips as corrupt, still counts there (a `fix` with `capture_source: "git_commit"` still closes its issue). `core/lessons` therefore decodes each line into a borrowed `Record` with the same rules, reusing the M1 object decoder (last duplicate key wins) and Python's truthiness, instead of building an `EventLog`. It is also cheaper: the hook needs ten fields and no indexes.
2. **The baked binary is the running executable.** Python bakes the `djf` next to the running interpreter, then `PATH`. Rust bakes the `djf` (then `dejafix`) next to `std::env::current_exe()`, then `PATH`, then bare `djf`; the hook's runtime `command -v` fallback is unchanged. On Linux `current_exe` is the resolved path, so a Homebrew install bakes its versioned cellar path; logged in `improvements.md` (prefer a `PATH` entry that resolves to the same file).
3. **`DJF_BIN` is escaped for the shell.** Python embeds the path verbatim between double quotes, so a path containing `"`, `$` or a backtick breaks the hook or runs a command. Rust escapes those three with a backslash (backslashes are already slashes). Every ordinary path produces Python's bytes.
4. **Hook files are written through symlinks, as Python does.** `.git/hooks/*` is never cloned, so a symlink there was made by the user (a shared hook script); replacing it would break their setup. Existing hooks are rewritten in place with `fs::write` and `chmod`, new ones created with `create_new`. This is the one place Rust does not use `write_atomic`.
5. **Git calls run in parallel inside precheck.** Python runs `git log` for churn and for staleness per file, one after another. Rust starts all of them at once on scoped threads (one per query, bounded by the number of files checked) after reading the log, which is what keeps `djf precheck` inside 20 ms. Results are identical; the order of the output is the order of the files.
6. **Only files that have events cost a churn query.** Python skips files without events before asking git for churn (`if not file_events: continue`); Rust decides that before starting the queries, so the same git calls run.
7. **Colour follows the terminal.** Python's `typer.echo` strips ANSI escapes when the stream is not a terminal; Rust writes the escapes only when stdout (or stderr, for stderr lines) is a terminal. Piped output is byte-identical; terminal output too.
8. **Precheck output is always UTF-8.** Python falls back to `-` rules and `?` replacements on a non-UTF-8 console (`_rule`, `_console_safe`); Rust writes UTF-8 everywhere, as M2 decided for the other commands (on Windows std writes to the console through `WriteConsoleW`).
9. **The edit hook's call log is diagnostic and not byte-identical for errors.** The `error` field holds `{PythonExceptionName}: {message}` from a mapping of `io::ErrorKind` (`PermissionError`, `FileNotFoundError`, `NotADirectoryError`, `IsADirectoryError`, else `OSError`) and Rust's message text; every other field matches Python's record.
10. **Non-UTF-8 hook payloads are malformed.** Python's `json.loads(bytes)` also accepts UTF-16 and UTF-32 with a BOM; no client sends those. Rust accepts UTF-8 with or without a BOM; anything else is silent, as malformed JSON is.
11. **Session markers interoperate with Python's.** The directory `$TMPDIR/djf-edit-hook-{uid}`, its 0700 and owner checks, the per-session/per-agent layout, the CRC-32 file names and the report text inside are the same, so switching between the Python and Rust hook in one session keeps the "shown once" state. `getuid` comes from `rustix` (std has none and `unsafe` is forbidden). `O_NOFOLLOW` is not needed: the pending file is opened with `create_new` (`O_CREAT | O_EXCL`), which never follows a symlink.
12. **The snooze note does not regenerate `summary.md`**, exactly as Python's `set_snooze`, so the next write picks it up. Auto-capture regenerates, as Python does.
13. **Auto-capture and precheck use the working directory as the project root,** as Python does (`root or Path.cwd()`, `.dejafix` must exist there; the walk-up of other commands is not used). Git runs hooks at the top of the work tree.
14. **A git query that cannot answer is `None`, never an empty answer.** The runner returns `None` on spawn failure, non-zero exit or the 5 s timeout (the child is killed); stdin is always detached (`test_git_helpers_detach_stdin_and_keep_timeouts`).

## Found during implementation

- **Subagents.** Tasks 2 and 4 ran as two parallel subagents in their own worktrees (sonnet), Task 11 as one (opus); their commits were cherry-picked. Worktrees for subagents start from `main`, so each brief must say to reset to the branch tip first.
- **Interfaces as built.** `capture_event`/`merge_event` return `Option<Event>` (a summary is never empty, but `Summary::new` is fallible); `first_line` returns `String`. `HooksReport` gained `unreadable` (a hook that is not UTF-8 text is left alone with its own warning; Python crashes there). `find_stale` takes `Option<&HashSet<&str, S>>`. The edit hook reads `events.jsonl` with `read_events_unlocked`, so a writer holding the lock never delays an edit (Python takes no lock either). The git runner returns `GitFailure::{Exit, Unavailable}`, so `last_changes` retries the `--root` form only after a non-zero exit, as Python does.
- **Global gotchas file.** The golden scenarios found that `GlobalStore::append_gotcha_if_new` (M2) created an empty `library_gotchas.jsonl` on every attempt, decision or note; Python creates it only when a gotcha is promoted. Fixed: the file is opened without `create` and made only when an entry is written.
- **Seen markers** are written with platform newlines and compared after universal newlines, so Python's and Rust's markers stay interchangeable on Windows too (Decision 11).
- **Precheck process.** `git diff --cached` starts while the log is read and parsed; churn (`git log --since=30.days.ago --oneline`, exactly Python's query) and staleness run in parallel, at most 8 git processes at a time. A variant with one `git log` per file for both answers was tried and dropped for parity (logged in `improvements.md`).
- **Budgets** (release build, 3,000-event fixture, macOS arm64 under a load average of about 12, outside the sandbox): edit hook 5.3–10.0 ms criterion mean across runs (budget 10 ms), median about 7 ms; `djf precheck` with one staged cited file 29 ms median against the 20 ms budget, `djf precheck <file>` 24.5 ms, `djf precheck` on a file without events 8.9 ms, Python 176 ms. One git process costs 6–9 ms on this machine (`git --version` 9.9 ms against 3.8 ms for `/usr/bin/true`), and the staged path needs two in series (the staged list, then the history of those files), as Python's design does; the dejafix share of the run is about 9 ms. The final criterion run (load average 9.7) gave edit hook 5.9 ms, precheck 41.4 ms, bare `git diff --cached` 16.7 ms and `precheck <file>` 40.1 ms: git's start-up dominates and scales with machine load. **The precheck budget is not met on this machine** and waits for the user's decision (see the hand-over and `improvements.md`, "One git query per file for churn and staleness").
- **Golden coverage.** `hooks_match_python`, `auto_capture_matches_python`, `precheck_matches_python` and `edit_hook_matches_python` are byte-identical after normalising the baked `DJF_BIN` path, temp roots and `HH:MM UTC`; 31 golden tests in total.
- **Verification.** `just verify` green (541 tests; core 96.5 % lines, binary 90.4 %), `just golden` 31/31, `just smoke` installs the binaries, commits through the installed hooks with `PATH=/usr/bin:/bin` and finds the auto-captured event, runs precheck and the edit hook.
- **Reviews of M3.** Round 1 (`/code-review high`, 10 findings), all fixed: the edit hook no longer waits for the log lock; precheck went back to Python's exact churn query (the single-query variant walked far more history for files without claims and changed git's `--since` semantics); the staged-file query starts only after the snooze check; an unreadable hook gets its own warning; `Prefetched`, `Normalizer`, the `Found` alias and `GitHistory` moved into `types.rs`; the edit hook reuses the adapter's `posix`, `MEMORY_DIR` and `events_path`; a capture whose regeneration failed prints nothing, as Python; `edited_paths` runs once per call; seen markers are newline-compatible with Python on Windows. Round 2 (4 findings): fixed — churn queries run on at most 8 workers, `last_changes` retries the root form only after a non-zero exit, `mention` lost an unreachable special case; skipped — reading the log before knowing whether anything is staged (the overlap with `git diff --cached` is what keeps the pre-commit path fast; a run with nothing staged pays about 3 ms). Security review: no finding at confidence 8 or above; eight below it (hook writes through user symlinks in `.git/hooks`, a symlinked log read into the hook context, pathspec magic in logged paths, terminal escapes in summaries, the unredacted auto-capture echo, the snooze file through a symlinked `.dejafix`, an existence probe for absolute locations, temp-dir races) are Python's behaviour or covered by the marker checks; the pathspec and echo ones are in `improvements.md`, terminal escapes already were.
